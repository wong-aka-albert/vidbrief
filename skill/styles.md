# 风格:先定轮廓,再往里填内容

报告的差别不在"用词活泼还是严肃",而在**轮廓**:讲几点、每点按什么顺序写、给谁看、要不要证据。
同样一份材料,按「快扫版」和按「教学版」写出来是两份不同的东西 —— **换风格 = 重写一遍轮廓下的内容**,
不是把语气词换一换。

所以:**报告动笔之前,先把风格定下来**(这条是 `build_report` 的必填项 `style`)。

## 1. 定义一份报告轮廓的七维

| 维 | 取值 | 它决定了什么 |
|---|---|---|
| **粒度** | 概括 / 标准 / 详细 | 条数与每条篇幅(**按视频长度换算**,见下) |
| **顺序** | 结论先行 / 推导先行 / 顺时间线 | 每条第一句是什么;读的人先看到结论还是先看到依据 |
| **每条骨架** | 固定几段 / 连着写 | 是分段小标题,还是段落叙事 |
| **术语** | 行话 / 首次出现即解释 / 少术语 | 读者的门槛 |
| **证据密度** | 少图 / 每条挂图 / 图最重 | 面板里出几张图、引不引讲者原话 |
| **可操作性** | 不写 / 写边界 / 写边界 + 怎么用 | 读的人能不能照着做 |
| **语气** | 平实 / 大白话 / 诙谐 / 叙事 / 行业腔 | `tone` 那一栏(自由文本) |

**粒度按长度换算,别按"感觉"**:视频 16 分钟和 2 小时,同样的档位条数差一个量级。
一律用"**每 10 分钟几条**"来估:

| 档位 `granularity` | 每 10 分钟 | 每条篇幅 |
|---|---|---|
| `brief` 概括 | 3–6 条 | 1–2 句 |
| `standard` 标准 | 6–12 条 | 一段到三段 |
| `detailed` 详细 | 12–20 条 | 3–6 段 |

## 2. 五种预置风格(开箱即用)

每种都给了**轮廓**,照着往里面填内容。属性可以按用户的要求单独改某一维,
但**改动要落在 `style` 里**(见 §4)。

### 快扫版 `quick` —— 看过视频的人,扫一眼想起来

- 粒度 `brief`;顺序 **结论先行**;骨架:结论 → 一条依据(图或原话)
- 术语按**行话**;证据**少图**(一条最多一张);不写"什么时候不适用"
- 语气:平实、干脆。**适合**:"我看过一遍了,就要个索引""别解释,给我要点"

### 教学版 `teaching` —— 没基础的人,要真学会

- 粒度 `detailed`;顺序 **推导先行**(先摆现象与依据,再落结论)
- 每条骨架固定五段:**这一步在解决什么 → 讲者的说法 + 我的翻译 → 依据(画面/原话) →
  什么时候不适用 → 怎么用**
- 术语**第一次出现就用一句人话解释**;每条挂图 1–3 张 + 引讲者原话
- 语气:大白话。**适合**:"我没接触过这行""给新人看""讲清楚点"

### 故事版 `story` —— 想顺着一趟听下来

- 粒度 `standard`;**顺序 = 视频的时间线**(不重排、不归类)
- 骨架**连着写**(少用列表与表格),每段开头交代"现在讲到哪"
- 术语少用,遇到打比方;图挂在转折处
- 最后一条收口:这一趟走下来该记住什么。**适合**:"按顺序讲一遍""别一堆表格"

### 元组版 `review` —— 拿它回看自己的操作

- 粒度 `detailed`;**每条固定四段:当时怎么判断 → 画面证据 → 结果 → 现在怎么用**
- 图**最重**(读的人要能对着画面核),画面上的数字照抄
- 术语精确、不换说法;必写"这次对/错在哪、下次看什么"
- **适合**:"我要对照自己的单子看""拿它检查我哪里想错了"

### 汇报版 `exec` —— 给没看过视频的人交代这件事

- 粒度 `brief`;每条 **结论 → 影响 → 建议动作**,最多三句
- 术语用行话、不解释;**基本不挂图**;不写推导过程
- 语气平实、去情绪。**适合**:"给老板/同事看""我要的是结论"

### 自定义 `custom`

用户的要求拼不出上面任何一种(比如"用表格给我一份对照清单,每条要有原始时间戳")——
用 `custom`,并把**要求原文**写进 `style.notes`,按它去定轮廓。

## 3. 怎么按用户的话挑

用户不会说"我要教学版",他说的是场景。按这张表翻:

| 用户这么说 | 选 |
|---|---|
| 我看过/复习/索引/要点/别解释 | 快扫版 `quick` |
| 没基础/刚入门/新人/讲清楚/我不懂这行 | 教学版 `teaching` |
| 按顺序/顺着讲/别一堆表格/当故事听 | 故事版 `story` |
| 元组/对照我的操作/检查我哪里错了/拿它核 | 元组版 `review` |
| 给老板/给同事/汇报/结论先行 | 汇报版 `exec` |
| 说了具体要求但有一样对不上(比如"要表格") | 自定义 `custom` + 要求写进 `notes` |

**用户没交代**时:按材料的性质挑,拿不准用**教学版**(它对读者最宽容 —— 讲清楚了,
懂行的人也能扫),并且**交付时必须说清这一版是按什么风格做的**
(「这版是教学版:条数多、每条讲透;要换成快扫版说一声,我重出一份」)——
用户才知道该不该让你换。

## 4. 落到工具参数里

`build_report` 的 `style` 是必填的,四项:

```json
{
  "preset": "teaching",          // 上表里那个名字;拼不出预置就 custom
  "granularity": "detailed",     // 粒度:brief / standard / detailed(§1 的档位)
  "tone": "大白话,术语第一次出现就解释",   // 语气:自由文本,用户怎么说就怎么写
  "notes": "给刚入行的人看;边界条件要写清楚" // 可选:还有别的交代写这儿
}
```

- `preset` 是**轮廓的名字**,`granularity` / `tone` 是**这一版实际用的两条属性** ——
  用户说「教学版,但语气随意点」时,`preset` 还是 `teaching`、`tone` 改掉,
  这样重跑时看得出差在哪。
- 页面标题栏会显示这一版(「教学版 · 详细 · 大白话」),`report.md` 的头一行也是同一句 ——
  用户看到就知道该不该让你换。
- **换风格就是换轮廓**:用户说"换个风格",别只改语气,按新预置把条数、每条骨架、
  详略重来一遍(`build_report` 整份替换)。
