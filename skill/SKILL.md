# vidbrief 技能:把一部长视频做成能对着看的图文总结

这套技能管**怎么写**,不管"工具怎么调"。两边分工:

| 你要的东西 | 去哪儿拿 |
|---|---|
| 工具的参数、门的规矩、报错怎么解 | **工具自己**(`get_guide(step=…)` 或提示模板)—— 它随二进制走,是权威 |
| 一步做完该停下来给用户看什么 | 同上(每步的 `get_guide`) |
| **怎么写**:选哪些点、每条写成什么形状、什么风格 | **本目录**(`workflow.md` / `styles.md`) |
| 工具一行一个的速查 | `tools.md`(**自动生成**,只是地图;细则在上面第一行那个权威里) |

> **两侧不许互相抄**。工具侧的说明是接口契约(里面写了某个工具,那个工具就必须存在);
> 这里写的是手艺 —— 手艺会变,变了改这儿,不用动工具。

## 四步,一步一停

vidbrief 把"长视频 → 图文总结"拆成四步,每一步的产物用户能直接看:

1. **前处理**(`preprocess`):差帧图 / 密集区 / 截图 / 转录 —— 纯算法。**长视频别赌一次调用**:
   作业跑在独立进程里,默认只等 180 秒;等不够就再调一次 `preprocess` 接着等
   (`preprocess_progress` 看进度,`preprocess_result` 取结果)。
2. **校准**:逐张看图(`record_shot_check`)、通读转录(`get_transcript` 按**组**给,
   一组是一口气说完的一小段;改动用 `apply_corrections` 报回 —— **加断句也在这一趟报**,
   ASR 的输出几乎不带标点)。
   **画面是第一依据** —— 转录听错的名称、版本号、术语,只有看图能改对。→ 看 `workflow.md` §2
3. **总结**(`write_summary`):图文互证之后写 —— **一段一段交**,每段带它讲的时刻
   (`t`);最后单独交一条**总述**(不带 `t`)。这一段就是报告页上的一条。→ `workflow.md` §3
4. **报告**(`build_report`):把那些段摆成**挂在时间轴上的知识点** ——
   用户边看视频边对照的那一页。**这一步不写内容**:你只交代口味(`style`),
   要改内容回第 3 步改段。→ `workflow.md` §4 + **`styles.md`(先定风格)**

**每步做完停下来**,把产物给用户看,问他要改哪儿。报告做完要说清"这一版是按什么风格做的"。

## 五条铁律(踩过坑才写下来的)

1. **判断归你,工具只做机械的事**。工具能查"这张图在不在清单里""这句原话抄得对不对",
   但它不会替你判断"这个点值不值得讲"。
2. **不许编 —— 但也不许把"看不清"静默略过**。三条路,按"它是不是结论的支柱"分:

   | 情况 | 怎么写 |
   |---|---|
   | 看得清 | **照抄**画面上的字 |
   | 看不清,**结论不靠它** | 不写那个数(写了就是编) |
   | 看不清,**结论靠它** | **照写结论 + 一起写出"它不确定"**,并记一条**待核验** |

   第三条是关键:一个数字如果是结论的支柱,略过它等于**悄悄削弱结论** ——
   读的人看不出少了什么。正确做法是把它写成带不确定性的形式
   (「约 3.12 一带(这个版本号画面看不清,待核验)」),并在报告里挂一条
   "核什么、去哪儿核"(「回看 8:05 确认那根代码的下沿」),交付时把这个数报给用户。

   查不到的背景同理:**别补,但可以说清"材料里没说"** ——
   "不知道"是个结论,"不说"不是。
3. **原话不用你抄**。讲者在那一刻说了什么,工具按锚点时刻自己去转录里取 ——
   你要给的是**判断**(哪一刻值得单独讲、这条讲什么),不是打字。
   只有"这条讲的是别处那几句"时才显式给段号。
4. **听到指代词就去看图**。「这一段」「那一段」「这根线」「这个位置」是**指着画面说的** ——
   话只说了一半,另一半在图上。这类地方**必须取图查证**,并把指代在产出里解开
   (「他说的『这一段』= 图上 7:45–9:30 的代码」);解不开就写清解不开,别猜。
   见 `workflow.md` §0.1 那张表。
5. **工具断了就停,别接着往下写**。断线的样子:报错里出现「管道正在被关闭 / broken pipe /
   connection closed」这类**传输层**的话,或者调用**根本没返回**。那是**连接断了,
   不是你调错了** —— 这时:
   - **停下来**,把已经做完的那一步的产物指给用户看(路径 / 页面),说清断在哪一步;
   - **不要凭记忆接着写材料**(总结、报告都算)—— 那样写出去的东西**没经过工具校验**,
     而用户会以为它是过了门、锚点核过的那一份;
   - 更不要把**没落盘的东西说成已落盘**。重连之后先看一眼进度(`get_project`),
     再决定从哪一步接着走。
   - **步 1 例外**:前处理是一趟跑在**独立进程**里的作业,连接断了它还在跑 ——
     重连后 `preprocess_progress` 看一眼、`preprocess_result` 取结果即可,
     **别重开**(还在跑时开新的只会接着等这一趟)。

## 目录

- `workflow.md` —— 四步的流程与规范:选点、图文互证、溯源、每条知识点的骨架、常见坑;
  **§0.1 是「指着画面说」的话术表**(哪类话必须去取图),§4.6 是看不清的数字怎么标
- `styles.md` —— **风格偏好**:用哪几维定义一个报告的轮廓 + 五种预置风格(开箱即用)+ 怎么按用户的话挑选风格
- `tools.md` —— 工具速查(**自动生成,别手改**:它是活的工具表的投影,
  过期了有测试会红)
