# 流程与规范:一部视频怎么变成一份能看的总结

> 工具怎么调看 `get_guide(step=…)`(权威)。这里只写**手艺**:怎么选、怎么写、别踩什么坑。
> 风格(报告的轮廓)另见 `styles.md` —— **报告动笔之前先把风格定下来**。

## 0. 总原则:图文互证

一部教学/讲解类视频里,信息有三个来源,可靠度不一样:

| 来源 | 可信度 | 用法 |
|---|---|---|
| **画面**(截图) | 最高 —— 名称、版本号、规格、形态、PPT 上的字都印在上面 | 定案 |
| **转录** | 中 —— 同音字、术语、数字最容易错 | 用画面校 |
| **外部资料** | 补背景用,不是定案依据 | 材料没说清的才查,并给出处 |

**"主讲人说错了"和"转录听错了"是两回事**,别混:前者照讲者原话记,后者用画面改。

### 0.1 「指着画面说」的话术:听到就得去看图

讲者是**对着画面**讲的,于是有大量话**只说了一半** —— 另一半在图上。
只读转录会一头雾水(「他说的是哪一段?」),而这正是图文互证最该发力的地方。
**这类话术是"必须取图"的信号**,不是可以顺着读过去的修辞:

| 话术 | 例子 | 省略的是什么 | 怎么查 |
|---|---|---|---|
| **指代区间** | 「这一段(数据)」「那一段运行」「前面这波」「后面那段」 | 起止位置(从哪根 图表到哪根、哪个版本号到哪个版本号) | 取该时刻的图,把区间落到具体范围上;必要时取前后两张对照 |
| **指代画面元素** | 「这根线」「这个框」「这一带」「上面这个」「蓝色这一点」 | 是哪个元素(配置项 / 灰框 / 参考线 / 标注点) | 看图上的标注与颜色,把"是什么、画在哪儿"写出来 |
| **指代数值** | 「这个位置」「这个版本号」「3.12 这里」 | 具体数字 | 读画面上的数字,**照抄**;看不清就走 `verify` 待核验(§4.6) |
| **指代次序** | 「第一种」「刚才那个」「接下来这个」 | 前文哪一条 / PPT 上的第几项 | 回转录找上下文,或在图上找条目编号 |
| **指代名称·规格** | 「这个东西」「结构图」「这边」 | 名称、周期 | **画面上的标题与标签**——转录的同音字错多半就在这儿定案 |
| **指代比较** | 「比刚才那个强」「不像上一张」 | 对照的是哪一张 | 两张图放一起看 |
| **演示动作** | 「我这样画一下」「把它断开」 | 画面上刚出现的那个标记 | 取动作前后两帧(差帧图的密集区就是干这个用的) |

**听到就做三件事**:

1. **取图**:在那一刻 `get_shot`(没有就 `extract_shot`)—— 把"他说的是画面哪一块"看清楚,
   结论写进这一条的看图记录。
2. **在产出里把指代解开**(写作时的硬要求):读者看到的不能是「他说『这一段』」,
   而要是「他说的『这一段』= 图上 7:45–9:30 那段代码(灰框)」。
   **把指代词照抄给读者 = 把疑问原样递下去。**
3. **解不开就说解不开**:图上找不到对应物(他指的是别处的图 / 图被切掉 / 画面糊)
   → 写清"哪句话指代不明、我看了哪张图仍然对不上",并挂一条 `verify`。
   **别猜一个范围填上** —— 猜错的范围比"看不出"更坏。

> 一句话:转录告诉你**他说了什么**,图告诉你**他指着什么说**。缺一半都不算读懂。

## 1. 前处理之后先建结构,别急着写

通读转录 + 看密集区(画面切换点 ≈ 内容切换点)+ 截图清单,先得到"总—分"骨架:

- 这一期在讲什么、分几块、每块大概哪一分钟到哪一分钟;
- 哪几处**值得单独讲**(一个概念的界定、一次图表的切换、一个案例怎么展开);
- 哪几处是**过场**(自我介绍、下期预告)—— 不进总结。

> 骨架先给用户过一眼再往下写,比写完再返工便宜。

## 2. 校准:画面是第一依据

- 逐张关键图看一眼,写下结论:**图上是什么** + **和同时期的语音对不对得上**。
- **步 1 可能已经把纯色帧预标成 `drop`**(切黑 / 淡出 / 纯色占位,`reason` 里写着为什么)
  —— 那是算法的粗筛,不是结论:弃用的不进待校准那一批,**不用为它花一次看图**;
  真觉得那张图有用,`update_shot(keep)` 改回来再看。
- 转录逐段核:听错的术语、同音字、数字。**改完要报回工具**(审过没问题的段也要报),
  不然门看不见"你审过"。
- 拿不准的两种情形分开:
  - **我看不清** → 写清看不清的是什么(别猜);
  - **我定不了** → 明确说"这条要用户拍板",交给用户。

## 3. 总结(整篇)

一篇总结回答四个问题,顺序自己定:

1. **一句话主旨** —— 这一期到底想让人记住什么;
2. **结构** —— 跟着视频的走法(总分总 / 顺时间 / 问题-答案),给时间坐标;
3. **关键概念** —— 术语是什么意思、**什么时候不适用**;
4. **材料状态** —— 图上核过什么、转录改了什么、哪些是用户裁定的。

规矩:
- **溯源**:每个结论能追到"哪张图 + 哪句话(时间戳/段号)";
- **不复述**:转录是"他说了什么",总结是"读懂了之后是什么意思";
- 用户不满意 → 带上旧稿改(先读旧稿,再动笔)。

## 4. 报告:挂在时间轴上的知识点

报告不是总结的复制品 —— 它是**边看视频边对照**的一页:时间轴上一个圆点就是一条知识点,
点它跳到那一刻,右边是图文面板。

### 4.1 选点是全部功夫

**视频里逐个讲的,报告里逐个成条**:一个个知识点、一个个步骤、一个个知识点,
每一个各占一条 —— 它被讲到的那一刻就是它的锚点,它自己的画面就是它的证据。

把六个案例合成一张表塞进一条,读的人在时间轴上点不到某一个案例,在面板里也翻不到
"这个案例讲了什么"。**那是把内容埋了,不是省事。**

两头都不许:不堆空标题(每条都要说透),也别把几条并成一条。

### 4.2 每条知识点的骨架

按这个顺序写(风格不同,详略不同 —— 见 `styles.md`):

1. **这一步在解决什么**(一句话,能当标题);
2. **讲者的说法 + 我的翻译**:原话照抄,再用自己的话讲清(术语第一次出现就解释);
3. **依据**:当时画面上是什么(挂图)、讲者原话是什么(引用);
4. **边界**:什么时候不适用、容易误解成什么;
   有**待核验**的数字(看不清但结论靠它)在这儿写清它是怎么估出来的;
5. **怎么用**(可操作的内容):看到什么就该做什么。

**不要写"见上文""如前所述"** —— 读的人是跳着看的,每条要能自己站住。

### 4.3 来源:每条都要有,而且要能核

- **讲者原话**:`quote` **一字不差**照抄一句。工具拿它去转录里找段号,**找不到就拒收**。
  别跨段拼、别顺手润色 —— 那是"这句话确实在材料里"的唯一证明。
- **外部补充**:材料没说清的术语/对象/事件才联网查,给一句话大意 + 能点开的链接。
  **查不到就别编** —— 链接点不开同样会被拒收。

### 4.4 图:挂"说明了这一条"的图

- 图在截图清单(`list_shots`)里挑,不在清单里的引不了;
- 视频画面上已经有了的东西不必再摆一遍(但**关键画面**要挂:读的人要能对照);
- 一条挂 1–3 张就够,别把一屏图堆在一条上。

### 4.5 常见坑(实测踩过的)

| 坑 | 症状 | 怎么防 |
|---|---|---|
| **quote 抄歪** | 多一个"我们"、少一个标点 → 工具拒收 | 从转录里**复制**,别凭记忆重打 |
| **数字想当然** | 版本号/规格/比例写成"差不多"的值 | 画面上的字照抄;看不清就不写那个数 |
| **静默略过关键数字** | 结论靠的那个数看不清,就不提了 —— 结论看着照样成立 | 它是支柱就必须**连不确定一起写出来**,并挂一条**待核验**(见 §4.6) |
| **回指** | "如前所述""见上文" | 每条写完自己念一遍:单看这一条懂不懂 |
| **乱码字符** | 正文里出现一个方块(U+FFFD) | 编码坏掉留下的,重写那一句;工具会拒收 |
| **合并成一条** | 六个案例挤成一张表 | 逐个讲的逐个成条(§4.1) |
| **粒度跑偏** | 该细的地方一句话带过,该快的地方写三段 | **动笔前先定风格**(`styles.md`),条数与篇幅按档位来 |

### 4.6 看不清的数字:待核验

一条知识点可以带 `verify`(字符串数组):**读的人该回头核一下的点**。它主要接住:

- 画面上的数字看不清,而**结论靠它**(版本号、规格、比例、边界值);
- 屏幕上的字被挡了一半、分辨率不够、一闪而过;
- 你按同款结构或上下文推出的数(「按前面那张图的量级估的」)。

写法:结论照写,不确定性一起写进正文,核验方式写进 `verify`:

```json
{
  "title": "样本:这一段版本号",
  "body": "…讲者说这一带是版本号,**约 3.12**(这个版本号画面看不清,按标注位置估的;待核验)。",
  "verify": ["回看 8:05 那张图,确认版本号是不是 3.12"]
}
```

规矩:
- **不许静默略过** —— 支柱性的数字略过,等于悄悄削弱结论,而读的人不知道;
- **也不许把它写成确定值** —— "约 / 待核验 / 按……估的"这些词要留在正文里;
- **交付时报这个数**:"有 3 处待你核验"(报告页的标题栏也标着),别让它躺在数据里。

## 5. 交付:每次都要说清"这一版是什么"

- 报告做完:`url` 给用户 + **这一版用的是哪种风格**("这版是教学版;要换成快扫版说一声")
  + **待核验几处、是哪几处**(工具返回与页面标题栏都给了这个数);
- 用户提意见:带上旧数据再调一次(`build_report` **整份替换**);
- 用户说"换个风格":**换的是轮廓**(条数、每条骨架、详略),不是把语气词换一换 ——
  同一份材料按另一种预置重写一遍。
