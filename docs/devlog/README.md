# Devlog

记录开发过程的五个方面:**迭代安排、开发进度、重要决策、问题&解决方案、计划变更**。

与 commit message 配合(条目引用 commit、commit 引用条目 ID),可复原整个开发过程。

## 文件

| 文件 | 内容 | 可变性 |
|------|------|--------|
| `PLAN.md` | **当前**迭代安排(里程碑、待办、风险关注) | 常更新 |
| `YYYY-MM.md` | 该月的时间分档条目 | **只追加**,不改写历史 |
| `README.md` | 本文件:格式规范 + 检索手册 | 偶尔更新 |

> **本仓库只带这份规范,不带实际记录文件**(`PLAN.md` 与 `YYYY-MM.md` 都是本地开发档案,不入库)。
> 想要这套流程,按下面的格式自建即可。

> 原则:**历史只追加**。看法变了就新增一条(类型 `计划变更`),而不是修改旧条目。

## 条目格式

每条一个 `###` 小节,标题行格式固定:

```
### [YYMMDD-NN] 类型 · 标题
```

- **ID**:`YYMMDD-NN` = 日期 + 当日序号,全局唯一;**commit message 里引用它**
- **类型**(五选一):`决策` `进度` `问题` `计划变更` `迭代安排`
- 正文用固定字段名(按需取舍,但**字段名保持一致**,检索才准):

```markdown
- **标签**: `架构` `MCP` `清理`
- **提交**: `1a2b3c4` `1a2b3c5`
- **背景**: 为什么要做 / 遇到了什么
- **做法/决定**: 具体动作或结论
- **理由**: 为什么这样做
- **影响**: 对后续的约束、连带改动
```

## 检索

用 ripgrep(本机已装 `rg`)。**加 `-g '[0-9]*.md'` 可排除本 README 的格式示例行,避免噪声。**

示例里的哈希一律写成**假值**(`1a2b3c4`)。**别把真实哈希写进会发布出去的内容**:内容会被导出到
别的仓库,而哈希不跟着走 —— 留下的是指向空处的死指针。要留可回溯性,用**条目 ID**(内容自带的
稳定锚),或在私库给那次提交打个 tag;不要写进正文、示例与表格。

```bash
# 列出全部条目(按文件=时间顺序)
rg '^### \[' docs/devlog/ -g '[0-9]*.md'

# 按类型(把「决策」换成 进度 / 问题 / 计划变更 / 迭代安排)
rg '^### \[.*\] 决策' docs/devlog/ -g '[0-9]*.md'

# 按标签
rg '\*\*标签\*\*.*并发' docs/devlog/ -g '[0-9]*.md'

# 按时间(2026-09 档)
rg '^### \[2609' docs/devlog/ -g '[0-9]*.md'

# 全文关键词
rg '端口' docs/devlog/ -g '[0-9]*.md'

# 反查:某 commit 对应哪条记录
rg '提交.*1a2b3c4' docs/devlog/ -g '[0-9]*.md'

# 看某条完整内容
rg -A6 '^### \[260924-01\]' docs/devlog/ -g '[0-9]*.md'
```

无 `rg` 时的等价写法:

```powershell
Select-String -Path docs/devlog/*.md -Pattern '决策'
```

```bash
grep -rn '决策' docs/devlog/
```

## 与 commit 的配合

```
devlog 条目 [260924-05] ──引用──> commit 1a2b3c4
        ▲                              │
        └────────── 引用 ID ───────────┘
```

双向可达:从条目能找到当时的提交,从提交能找到当时的背景与理由。

> **最新条目怎么办?** 写条目时还不知道本次提交的哈希(哈希由提交内容决定)。
> 因此约定:最新的条目在 `提交` 字段写"本次提交",实际对应关系由 **commit message 里引用的条目 ID** 保证;
> 下一次提交时,若需要,可把哈希补记在新条目里(历史条目仍只追加,不回填)。
